# 기반시설 배치 최적화 계산 명세

상태: 추천 UI·오프라인 스킬 데이터·효과 계산·교대 시뮬레이터를 구현했다. 제한 시간 내 공동 배치 탐색이며 전체 스킬 지원 또는 전역 최적을 보장하지 않는다.
기준일: 2026-10-15 (Asia/Seoul).

## 1. 확정된 사용자 요구사항

- 보유한 오퍼레이터의 현재 정예화·레벨에서 해금된 기반시설 스킬만 사용한다. 육성 계획의 미래 상태는 사용하지 않는다.
- 모든 오퍼레이터는 최초 시작 시 풀 컨디션이다. 이후 교대에서 컨디션을 초기화하지 않는다.
- 계정별 시설 종류·레벨·정원·건설 여부를 반영한다. 미청소·미건설 칸은 배치 불가다.
- 제조소별 선택한 생산 품목을 유지한다. 시설의 생산 품목을 임의로 변경하지 않는다.
- 사용자가 순금·작전기록·오리지늄 조각의 우선순위를 정한다. 가중합 대신 1순위, 2순위, 3순위의 순서로 엄격하게 비교한다.
- 교대조 수는 2조 또는 3조다. 일반 생산 근무자는 조 간 중복 배치하지 않는다.
- 일괄 교대 기준은 첫 소진 시 / 전원 소진 시 / 12시간마다 중 선택한다.
- 숙소 추가 조작은 허용 / 허용 안 함 중 선택한다.
- 숙소 레벨·인테리어 점수·회복 스킬·정원·배치 순서를 반영한다. 인테리어 점수는 계정에서 불러오고 직접 수정할 수 있다.
- 모든 조의 배치에서 비소진 조건이 계속 성립하는 인원만 상주로 분류하고 조 간 공통 배치한다.
- 교대 때 생산물을 수거하고, 재료는 충분히 공급된다고 가정하며, 드론은 사용하지 않는다. 창고 포화로 인한 생산 중단은 반영한다.
- 제조소·발전소·무역소·사무실·제어센터의 배치를 함께 계산하며 숙소 회복도 함께 최적화한다.
- 무역소의 용문폐·합성옥 수익은 목적함수에서 제외한다. 제조소와 연계되는 무역소 정보까지 버리지는 않는다.

## 2. 생산량과 목적함수

- 생산량은 표시 생산력의 합이 아니라 실제 레시피 시간·완성품·창고 용량·가동 시간으로 계산한다.
- 순금은 생산 개수, 작전기록은 경험치량, 오리지늄 조각은 생산 개수로 비교한다. 실제 아이템별 개수도 별도로 출력한다.
- 무역소 수익과 재료 비용은 점수로 환산하지 않는다. 재료가 충분하다는 가정을 결과에 표시하고, 조각 생산에 필요한 재료량은 참고 정보로 표시한다.
- 비교 벡터는 사용자 순서로 정렬한 장기 시간당 평균 생산량이다. 서로 다른 단위끼리 더하지 않는다.
- 1순위가 같을 때만 2순위, 다시 같을 때만 3순위를 비교한다. 표시 반올림으로 동률을 만들지 않는다.
- 계산 오차 허용치는 수치 안정성 용도이며, 성능을 위해 1순위 손해를 허용하는 가중치로 사용하지 않는다.
- 점수가 모두 같을 때에만 추가 조작 횟수, 전체 배치 변경 수 등 편의성을 비교한다.
- 초기 창고·진행 중 생산·누적 스킬 값에 필요한 입력이 없다면 초기값 가정을 명시한다. 비교의 기준 상태를 통일하고 최초 풀 컨디션의 일시적 이득은 장기 점수와 분리한다.
- 수거되지 않은 완성품, 진행 중 생산, 레시피별 보관 무게를 추적한다. 교대나 수거 시 진행률을 임의로 초기화하지 않는다.
- 용량 관련 스킬이 소진 또는 이동으로 사라질 때 새 용량으로 포화 여부를 다시 판정한다. 완성품을 임의로 삭제하지 않는다.

## 3. 인원과 시설 제약

- 한 실제 인원은 같은 시각에 시설 하나에만 있을 수 있다. 근무·숙소·상주·특수 회복 임시 이동에 모두 적용한다.
- 아미야의 직군 형태처럼 동일 인물을 공유하는 데이터는 실제 인원 식별자로 묶는다. 별도 얼터까지 임의로 같은 인원으로 묶지는 않는다.
- 상주 인원도 시설 정원을 차지한다. 조마다 상주 인원을 새 인원처럼 복제하지 않는다.
- 일반 근무자는 정해진 조를 유지한다. 숙소 추가 조작으로 인한 일시적 회복 방문은 다른 조에 영구 편입하는 것으로 처리하지 않는다.
- 보조 시설 인원과 숙소 회복 담당도 전역 인원 풀을 공유한다.
- 생산 목적의 보조 시설 효과와 숙소 효과를 함께 평가한다. 각 시설이나 각 조를 순서대로 탐욕적으로 확정하지 않는다.
- 무역소 개수, 특정 오퍼레이터의 무역소 배치, 사무실에서 생성하는 자원 등 제조소에 연결되는 조건을 추적한다.
- 응접실·훈련실 등도 스킬이 참조하는 시설 레벨·배치 정보는 의존 조건으로 읽는다. 별도의 단서·훈련 수익을 목적함수에 추가하지 않는다.
- 드론 미사용이므로 발전소의 드론 회복 속도 자체를 생산 점수에 더하지 않는다. 발전소 배치가 제공하는 다른 연계 효과는 유지한다.
- 배치 인원 부족·휴식 공간 부족을 숨기거나 미보유 인원으로 채우지 않는다. 실행 불가 사유를 표시한다.

## 4. 스킬 해석

- 원본 buffChar의 각 스킬 계열에서 현재 육성 조건을 만족하는 유효 단계를 선택한다. 같은 계열의 이전·강화 스킬을 동시에 더하지 않는다.
- E2 Lv1이 E1 단계 스킬을 잃는 것으로 판정하지 않는다. 정예화와 해당 단계 레벨을 함께 비교한다.
- 단순 생산력, 품목 한정, 용량, 컨디션 소모·회복, 진영, 특정 동료, 시설 수·레벨, 파생 자원, 시간 누적, 컨디션 임계값, 배치·퇴실·소진 시 발동을 구분한다.
- 배율·가산·대체·상한·내림·동종 배타 효과의 순서를 개별 규칙으로 정의한다.
- 생산력을 0으로 대체하는 효과나 다른 효과보다 우선하는 규칙을 단순 가산하지 않는다.
- dorm 회복 관련 스킬의 컨디션 0 예외를 일반 생산 스킬 비활성화와 구분한다.
- 숙소 인원수가 제조소 파생 자원에 영향을 주는 경우 숙소 재배치·회복 담당 배치도 생산 평가에 반영한다.
- 기억 조각 등 누적 자원과 컨디션 소진 시 초기화 규칙을 상태에 보관한다. 단순 현재 배치표만으로 계산하지 않는다.
- 모든 buff에 계산 규칙 ID와 지원 상태를 기록한다. efficiency=0을 효과 없음으로 판정하지 않는다.
- 미지원 효과를 조용히 0으로 치환하지 않는다. 관련 후보와 결과의 한계를 표시하고 전역 최고 효율을 주장하지 않는다.

## 5. 시간 진행과 교대

- 컨디션 0, 풀 회복, 회복 대상 변경, 스킬 임계값, 시간 누적 갱신, 생산 완료, 창고 포화, 추가 조작, 교대를 이벤트로 다룬다.
- 이벤트 발생 후 시설 전체의 의존 효과를 다시 계산하고 다음 이벤트 시각을 구한다.
- 소진 후에는 영향을 잃은 생산·컨디션 스킬 때문에 다른 인원의 소진 시각도 바뀔 수 있다. 시작 시각에 계산한 시간의 단순 최댓값으로 전원 소진을 결정하지 않는다.
- 첫 소진 시: 현재 조의 교대 대상 근무자 중 최초 소진 시점에 일괄 교대한다.
- 전원 소진 시: 비소진 상주를 제외한 교대 대상 근무자가 모두 소진된 시점에 교대한다. 소진 후 생산력 저하를 시간에 따라 반영한다.
- 12시간마다: 첫 교대부터 매 12시간에 교대한다. 조가 3개이면 한 조의 복귀 간격은 36시간이다.
- 생산 연계 보조 시설의 교대 대상 인원도 교대 이벤트 판정에 포함한다. 숙소 회복 담당은 근무 소진 이벤트의 대상이 아니다.
- 전원이 비소진이면 소진 기준의 교대 시각은 없다. 이를 임의로 12시간으로 바꾸지 않는다. 생산 중단·수거 필요를 별도로 표시하고, 유한 교대가 없는 경우의 생산 평가 가정을 명시한다.
- 복귀 인원의 컨디션이 0인 경우 0시간 교대를 무한 반복하지 않는다. 해당 교대안의 실행 불가 또는 유지 불가를 표시한다.
- 같은 시각에 여러 이벤트가 발생할 때 컨디션·생산 진행을 먼저 해당 시각까지 적분하고, 완료·소진·회복 상태를 확정한 뒤 사용자 조작·배치와 효과를 재계산한다. 게임에서 순서 의존성이 있는 효과는 별도 검증한 순서를 사용한다.

## 6. 숙소와 추가 조작

- 숙소별 기본 회복은 시설 레벨과 유효 인테리어 점수로 계산한다. 회복량 단위와 레벨별 인테리어 상한을 게임 데이터로 검증한다.
- 자신·단일 대상·전체 대상 회복과 동종 배타 규칙을 구분한다. 필요할 경우 입실 순서와 대상 선택을 추적한다.
- 회복 담당도 한 자리를 사용한다. 3교대의 두 휴식조가 동시에 모든 자리를 이용한다고 가정하지 않는다.
- 추가 조작 허용 안 함: 교대 때만 입실·퇴실·순서를 변경한다. 교대 사이 회복 완료로 생기는 게임 내부 효과 변화는 계속 반영한다.
- 추가 조작 허용: 숙소 자리 교환, 회복 대상 교체, 조건부 컨디션 교환 등을 구체적 행동으로 계산한다. 각 행동의 시각·입실 순서·관련 인원을 결과에 포함한다.
- 특수 회복 때문에 근무자를 잠시 이동시키면 시설 정원·생산 중단·연계 스킬 변화·근무 시간 누적의 유지/초기화 여부를 처리한다.
- 추가 조작 허용을 무한한 무료 회복·즉시 복제로 처리하지 않는다. 행동마다 자원·인원·컨디션 보존과 발동 조건을 검사한다.
- 피아메타의 고정 회복과 컨디션 교환은 일반 숙소 회복 가산과 다른 규칙으로 처리한다. 재발동과 배치 순서는 원본 및 게임 동작 대조가 필요하다.

## 7. 반복 운용과 상주 검증

- 2조는 A→B→A, 3조는 A→B→C→A로 진행한다. 각 복귀 때 컨디션·누적 자원·생산 진행을 이어받는다.
- 조별 근무 시간이 소진 기준으로 달라질 수 있으며 숙소 휴식 시간도 그 실제 시간에 따른다.
- 복귀 시 풀 컨디션을 필수로 강제하지 않는다. 장기적으로 유지되는 상태인지 검증한다.
- 상주는 모든 조와 각 조 내부의 효과 변화까지 포함해 컨디션이 계속 감소하지 않는 경우에만 허용한다.
- 추가 조작으로 주기적으로 회복시켜 유지하는 인원은 비소진 상주와 구분해 조건부 유지로 표시한다. 자동으로 조 간 중복 금지의 예외를 넓히지 않는다.
- 포화·한도 없는 누적 변수를 포함한 경우 단순 컨디션만으로 반복 상태를 판정하지 않는다.
- 반복 상태 또는 수학적 유지 조건을 확인한 결과와, 유한 기간 시뮬레이션으로만 확인한 결과를 구분한다. 계산 제한에 걸렸다고 임의로 지속 가능으로 판정하지 않는다.

## 8. 현재 코드의 보완 필요 사항

- assets/js/base-state.mjs의 normalizeBuilding / prepareBase / readBase는 숙소 인테리어 점수를 보존하도록 확장했다. 기존 계정 서버를 사용하는 경우 서버 재배포 또는 수동 점수 입력이 필요하다.
- base.html의 좌우 스크롤 아래 설정 영역에서 Web Worker 계산기를 실행한다. 진행 표시·취소와 조건 변경에 따른 결과 무효화를 지원한다.
- 인원 판단은 현재 보유·육성 저장값을 사용하고 계획 패널 값과 분리한다.
- 누락된 생산 품목·오래된 계정 데이터·누락된 스킬 메타데이터를 자동 기본값으로 숨기지 않고 입력 보완이 필요함을 표시한다.
- 게임 데이터는 실행 중 외부 사이트 조회가 아니라 버전이 고정된 저장소 데이터로 준비한다. 실제 규칙에 필요한 진영·개인 식별·아이템 경험치 정보도 함께 준비한다.
- 계산은 UI와 분리하고 취소·진행 상태를 제공한다. 계산 제한 시 현재 최선의 추천과 탐색 미완료를 표시한다.

## 9. 검증 기준

## 사용자 요청 시 공동 결과를 활용한 개선

공유 데이터는 검토 브랜치의 `research/base-community.json`, 접수 코드는 `base-share.mjs`와 Workers에 있다.
사용자가 정밀 분석을 요청할 때 현재 게임 데이터·엔진 버전으로 먼저 재검증한다.
동일 조건의 기존 최고 결과를 기준선으로 보존하고, 여러 탐색 시작점과 긴 탐색 예산으로
개선 배치를 찾는다. 사용자 우선순위에 따른 사전식 점수로 비교하고 회복·상주·중복·보관한도를 확인한다.
기존보다 나빠진 결과로 교체하지 않는다. 작은 문제는 전수 비교로 탐색 품질을 측정한다.
근거가 있는 스킬 규칙 보완과 탐색 개선을 테스트와 함께 커밋한다.
미지원 스킬은 공동 제출 데이터만으로 게임 규칙을 추정해 지원 처리하지 않는다.
개선 결과에는 입력 조건, 데이터/엔진 버전, 계산 시간, 비교 점수와 보장 한계를 기록한다.
이는 모델 가중치 학습이 아니라 추천 데이터·계산 알고리즘의 지속적인 개선이다.

### 배포 조건
사용자는 99% 이상 검증된 것으로 판단할 때 배포하도록 요청했다. 테스트 통과율을
최적 효율 달성률로 표시하지 않는다. 현재 전역 최적해 또는 상한이 없어 99% 최적성은
입증하지 못한다. 공유 결과는 검토 브랜치에 보관하고 이 기준을 충족했다고 주장하거나
자동으로 정식 배포하지 않는다. 미지원 효과와 실제 게임 대조도 별도로 확인해야 한다.

최종 사용자 지침: 공유된 배치를 이용자에게 재사용/배포하지 않고 계산 로직 최적화 분석에만 활용한다.
사용자가 요청할 때 연구 결과를 바탕으로 로직 수정만 준비하며 추천 데이터 직접 배포는 하지 않는다.


## 2026-10-15 사무실 최우선 및 시설 스킬 제한
- 평가 벡터는 `[HIRE, ...사용자 제조소 우선순위]`로 고정한다. HIRE는 컨디션 소진 이벤트를 포함한 연락 작업량(기본 속도에서의 상당 시간)을 적분한 뒤 측정 근무 시간으로 나눈 평균 배율이다. 사무실이 없으면 0이다. 제조소 생산량으로 사무실 열세를 상쇄하지 않는다.
- 연락 갱신 횟수는 수시로 사용하여 저장 상한에 도달하지 않는다고 가정한다. 실제 갱신 횟수·완료 시각을 예측하는 기능은 아니다.
- 게임 데이터의 사무실 기본 배치 보너스 5%, 활성 스킬, 숙소 레벨, Blitz 자원, 정예 소속 시설 수, 특정 제어센터 동료, 제어센터 연락 보너스를 적용한다. 모집 슬롯 수 의존 및 미지원 자원 효과는 계속 제외한다.
- 근무 시설에 맞는 해금된 기반시설 스킬이 없는 인원은 후보와 배치 검증에서 제외한다. 숙소의 일반 휴식 인원은 회복 스킬 없이도 허용하며, 숙소 지원자는 숙소 스킬을 보유해야 한다.
- 기존 공유 자료는 저장된 점수를 믿지 않고 현재 로직으로 다시 계산한다. 공유 입력 스키마는 변경하지 않는다.
