# 옷장 전환 모션 1차 분석

업로드된 GameAssembly.dll과 버전 29 global-metadata.dat에서 옷장 관련 코드만 정적으로 확인했다. 확인된 일반 전환을 옷장 미리보기에 적용했다.

## 확인한 값

- 클릭 전환: 15프레임. `TweenToState`에서 코루틴 반복 횟수에 15를 전달한다.
- 드래그 종료 정렬: 5프레임. `_DoEndDrag`에서 `_ToState`에 5를 전달한다.
- 반복 대기: `UnityEngine.WaitForEndOfFrame`. 초 단위 시간이 아니므로 60fps 기준으로만 약 250ms / 83ms다.
- 상태값: 시작값과 목표값 사이를 프레임마다 균등하게 나눈다. 화면상의 모션 전체가 선형이라는 뜻은 아니다.
- 카드 상태 테이블: `[0, 0, 0.3, 0.5, 1, 0.5, 0.3, 0, 0]`. 이웃 값 사이를 선형 보간한다.
- 카드 투명도는 보간값의 제곱근, 흰 마스크 알파는 `(1 - 보간값) × 0.4`로 계산한다.
- 카드 경계의 가로 폭은 `_boundPerLenth × 보간값`으로 계산한다. Unity CoreModule의 호출 주소를 대조하여 `RectTransform.set_sizeDelta`임을 추가 확인했다. 초기 위치값 해석을 정정한다. 프리팹 `_boundPerLenth`는 153.89999389648438이다.
- 드래그 상태 변화량은 `-3 × 10⁻⁶ × dx × |dx|`이며 시작 상태 ±2 범위로 제한한다.

## 근거와 남은 확인

함수 주소와 데이터 위치는 동명의 JSON에 기록했다. 카드 테이블은 정적 생성자의 FieldInfo 참조를 메타데이터 필드 기본 데이터까지 추적하여 확인했다. 코루틴의 대기 객체 타입도 메타데이터에서 확인했다.

특수 전환 분기, 전체 카드 정렬 및 컨테이너 위치와의 결합, 현재 실행 중인 Lua 핫픽스 적용 여부는 추가 확인이 필요하다. 따라서 이 결과만으로 현재 인게임 동작 전체가 완전히 복원되었다고 판단하지 않는다.
